# 世界杯2026 预测看板 & 海报 — 交接文档

本文档说明项目的核心框架、核心逻辑、数据如何调整，以及给 AI 下达任务（写预测 / 改代码 / push）的标准格式与示例。

---

## 一、项目概览

一个 2026 世界杯的「AI 预测看板 + 社媒海报」项目，纯静态前端（HTML + JS），数据放在 JSON 文件里，靠定时脚本拉真实赛果。

### 文件结构

| 文件 | 作用 |
|---|---|
| `index.html` | **预测看板**（主站）。多标签页：晋级路线（首页）、赛程预测、预测战绩、积分榜、历史比分、球队、今日焦点 |
| `poster.html` | **社媒海报**。生成「明天比赛」的比分预测页 + 判断依据页，可截图发布 |
| `data/matches.json` | **赛程 / 比分 / 状态**（赛程真相，所有显示以此为准） |
| `data/predictions.json` | **预测数据**（`predictions` 对象）+ 战绩汇总 `summary` + 复盘记录 `records` |
| `scripts/update_data.py` | **定时任务**（GitHub Actions cron），从 football-data.org 拉真实赛果，更新 matches.json 与 records |
| `docs/末轮出线状态修正协议.md` | 小组赛**末轮**预测方法论 |
| `docs/淘汰赛预测协议.md` | **淘汰赛**预测方法论 |

### 数据流

```
football-data.org API ──(cron: update_data.py)──> matches.json（赛果/状态）
                                                  └─> predictions.json 的 records（复盘）
人工/AI 写入 ────────────────────────────────────> predictions.json 的 predictions（赛前预测）
index.html / poster.html ──(浏览器 fetch JSON)──> 渲染看板与海报
```

> ⚠️ cron 会**直接往 main 推 "自动更新" commit**。AI 每次 push 前要先 fetch+rebase main，常遇冲突，按「重置重放」处理（见第六节）。

## 二、四条铁律（任何任务都不能违反）

1. **改逻辑不改单场数据**，代码里不出现具体队名或比赛 ID（即：逻辑通用，不为某一场写死）。
2. **比赛时间是北京时间（BJT = UTC+8）**，日期判断必须转 BJT。
3. **海报不出现胜率%、推荐、稳等博彩词**（娱乐向，规避合规风险）。
4. **每次只做一件事**，做完告诉用户改了什么，等确认再继续。

## 三、核心数据结构

### 3.1 matches.json — 单场比赛

```json
{
  "id": 75,
  "date": "2026-06-30",        // BJT 日期
  "stage": "1/16决赛",          // 淘汰赛阶段；小组赛此字段没有，改用 group
  "group": null,                // 小组赛为 "A".."L"；淘汰赛为 null
  "home": "德国", "away": "巴拉圭",
  "home_score": 1, "away_score": 1,   // 法定（含加时）比分；未赛为 null
  "home_pen": 3, "away_pen": 4,       // 点球比分（仅点球决出的淘汰赛才有；否则无此字段）
  "status": "upcoming",          // upcoming / live / finished
  "bjt": "04:30"                 // BJT 开球时间
}
```

- **球队名是主键**：predictions 的 key、FLAGS（队旗）、RANKS 都靠队名匹配，**写之前务必和 matches.json 核对队名拼写**（如「刚果(金)」「乌兹别克」「沙特」是项目内的标准写法）。
- **点球场**：`home_score/away_score` 存 90/120 分钟比分，点球另存 `home_pen/away_pen`。看板显示成 `1 (3) : 1 (4)`，晋级方按点球判定。**不要把点球数塞进 home_score**。

### 3.2 predictions.json — 单场预测（predictions 对象）

key 格式 `"主队|客队"`：

```json
"德国|巴拉圭": {
  "win": 50, "draw": 28, "loss": 22,   // 主胜/平/客胜 百分比（指法定90分钟）
  "lean": "主胜",                        // 主胜 / 平局 / 客胜
  "scores": {
    "main":      ["1-0", "2-1"],        // 首选档（主队视角比分）
    "secondary": ["2-0", "1-1"],        // 次选档
    "upset":     ["0-1"],               // 冷门档
    "blowout":   []                     // 大比分档（仅实力碾压/刷净胜球时启用）
  },
  "analysis": "……",                     // 文字分析（见下方约束）
  "confidence": "中"                     // 高 / 中高 / 中 / 低
}
```

**analysis 字段约束：**
- 不出现胜率%、推荐、稳等博彩词（铁律3）。
- 球星名用**中文译名**（如 姆巴佩、哈兰德、加克波），不要留英文。
- 小组赛末轮：必须写出双方出线状态 + 做了什么方向修正（见末轮协议）。
- 淘汰赛：必须写「若进加时/点球，谁更可能晋级」（见淘汰赛协议）。

**比分命中判定**（海报"昨日战绩"用）：实际法定比分若出现在 `main + secondary + upset`（不含 blowout）里即算命中。点球不计入（足彩口径）。

## 四、核心渲染逻辑要点

- **BJT 换算**：`new Date(Date.now() + 8*3600000)`；明天 `+86400000`，昨天 `-86400000`。美东 ET→BJT 为 **+12 小时**。
- **deriveScores(home, away, jp)**（看板与海报共用思路）：先查 `主队|客队`，查不到再查 `客队|主队`（反向并翻转比分），所以预测 key 的主客顺序与 matches.json 不一致也能匹配。
- **晋级路线图**（index.html `renderBracket`）：对称树，决赛居中，左右半区镜像（32强→16强→8强→4强→决赛→冠军）。数据来自 matches.json 中带 `stage` 的比赛，未定槽位显示「待定」。各 `stage` 取值固定为：`1/16决赛`、`1/8决赛`、`1/4决赛`、`半决赛`、`决赛`。
- **海报分页**（poster.html `render`）：比分页每页 4 场、判断依据页每页 2 场，超出自动加页。标题按当日 `stage` 显示阶段（淘汰赛）或「小组赛」。
- **昨日战绩**（poster.html `yesterdayStat`）：取**最近一个已完赛日期批次**，统计法定比分命中数；全中时战绩条放大+金色高亮+「🎯全中」徽章。

## 五、给 AI 下任务的标准格式（含示例）

任务分两类，请按下面格式提，AI 会照办。

### 任务 A：写入 / 更新预测数据

> 固定开头一句 + 直接贴 JSON（key 用 `"主队|客队"`，结构同 3.2）。

**示例：**
```
把以下数据写入predictions.json的predictions对象，commit并push：
{
  "巴西|日本": {
    "win": 52, "draw": 26, "loss": 22, "lean": "主胜",
    "scores": { "main": ["2-1","2-0"], "secondary": ["1-0","1-1"], "upset": ["1-2"], "blowout": [] },
    "analysis": "……（球星用中文名，淘汰赛写明加时/点球倾向）",
    "confidence": "中"
  }
}
```
AI 会：① 核对队名与 matches.json；② 写入/覆盖对应 key；③ 校验 JSON；④ commit + push；⑤ 回报改了哪几场。
（若队名拼写与赛程不符，AI 会先停下来跟你确认，不盲写。）

### 任务 B：改代码 / 改显示

> 用自然语言描述「现象 / 想要的效果」，不用懂代码。

**示例：**
- 「海报里淘汰赛比赛卡时间后面还显示 null 组，没有组就别显示。」
- 「晋级路线图的点球场比分改成世界杯标准的 1(3):1(2) 格式。」
- 「今日焦点改成今天比赛全部结束后自动显示下一天的全部比赛。」

AI 会：定位根因 → 只改相关函数 → 必要时实时搜真实赛况核对 → commit + push → 回报改了什么。

### 任务 C：录赛果 / 加赛程

**示例：**
- 「南非vs加拿大这场比赛时间是北京时间6月29日凌晨3点，加进去。」
- 「这16场1/16决赛对阵和时间都出来了，你搜一下全部放上去。」（AI 会 web 搜真实赛程并按 BJT 录入）

## 六、Push / Git 操作规范（AI 内部执行，供你了解）

- 开发分支：`claude/relaxed-newton-vo6w37`，最终推送目标：`main`（已获授权）。
- 因集成 token 受限，push 走「临时加 PAT 远程 → fetch+rebase main → 校验 JSON → 推送 → 删除远程」流程。
- cron 经常在推送前往 main 落「自动更新」commit 造成冲突，处理方式：`rebase --abort` → `reset --hard` 到最新 main → 用脚本把改动**重新应用一遍** → 重新提交推送（不手工解 JSON 冲突）。
- commit message 结尾固定附带 `Co-Authored-By` 与 `Claude-Session` footer。
- **已知限制**：环境无法 GPG 签名，GitHub 上 commit 显示「Unverified」。这是环境限制，**不为此重写 main 共享历史**，可忽略该提示。

## 七、两套预测协议（务必区分阶段）

| 阶段 | 用哪套 | 要点 |
|---|---|---|
| 小组赛第1-2轮 | 纯实力+状态 | 不启用修正协议 |
| 小组赛**末轮**（第3轮） | `docs/末轮出线状态修正协议.md` | 出线状态分类、默契球、轮换、控签位、刷净胜球等动机修正 |
| **淘汰赛**（1/16起） | `docs/淘汰赛预测协议.md` | 出线/默契/轮换/签位/净胜球全部作废；回归纯实力+状态；平局(90分钟)上调、低比分、点球硬币降信心；写明晋级倾向 |

口径统一：`win/draw/loss` 与 `scores` 都指**法定90分钟**结果；加时/点球的晋级倾向写在 analysis 里。

## 八、新一轮淘汰赛上线时要做的事（清单）

1. web 搜真实对阵 + 时间，按 BJT 录入 matches.json（带正确 `stage`）。
2. 按对应协议生成预测，写入 predictions.json（建议按比赛日分批）。
3. 赛后由 cron 自动更新比分；点球场确认 `home_pen/away_pen` 正确、看板显示 `x(p):x(p)`。
4. 晋级路线图、海报会自动读取新数据，无需改代码（除非要新阶段标签或新展示需求）。
